# Резервные копии и восстановление

## Создание копии

`scripts/backup.sh` архивирует volume, имя которого задаёт `COUCHDB_VOLUME_NAME` в `.env` (по умолчанию `livesync-couchdb-data`). Для согласованного файлового снимка скрипт останавливает CouchDB на время архивации, проверяет архив и запускает сервис обратно. Во время этой паузы запросы к CouchDB недоступны.

Скрипт сохраняет только volume с базой. Compose-файлы, `couchdb/livesync.ini`, `.env` и volumes Caddy в этот архив не входят. Храните конфигурацию отдельно; резервную копию `.env` держите только в зашифрованном хранилище. Не добавляйте рабочий `.env` в Git или ZIP. Для Caddy можно отдельно сохранить volumes `livesync-couchdb_caddy-data` и `livesync-couchdb_caddy-config`; без них сертификат может потребоваться получить заново.

```sh
./scripts/backup.sh
```

Архивы сохраняются в `backups/` с правами владельца. По умолчанию копии старше 30 дней удаляются. Значение читается из `BACKUP_KEEP_DAYS` в `.env`; `0` отключает удаление. Держите свободное место на диске и периодически проверяйте логи.

Для ежедневного запуска через cron сначала запустите backup вручную, затем добавьте строку, заменив путь на фактический:

```cron
0 3 * * * /absolute/path/livesync-couchdb-repo/scripts/backup.sh >> /absolute/path/livesync-couchdb-repo/backups/cron.log 2>&1
```

Это локальный backup на том же сервере. Копируйте архивы на отдельный носитель или удалённое хранилище; шифруйте их до отправки. CouchDB metadata может содержать чувствительные имена/пути даже при включённом E2EE.

## Проверка и восстановление

Скрипт распаковывает архив в новый Compose volume и временно запускает изолированный контейнер без сети. Он проверяет health endpoint и доступность базы. Текущий volume и запущенный сервис не меняются.

```sh
./scripts/restore.sh backups/couchdb-YYYYMMDDTHHMMSSZ-id.tar.gz
```

После успешной проверки скрипт напечатает имя нового volume. Переключение делается отдельно:

1. Остановите синхронизацию на всех Obsidian-устройствах и сохраните копию их локальных изменений.
2. Замените `COUCHDB_VOLUME_NAME` в `.env` на имя восстановленного volume и установите `COUCHDB_VOLUME_EXTERNAL=true`.
3. Выполните `docker compose up -d`.
4. Проверьте health status и заметки из тестового ваулта.

Старый volume остаётся на месте и позволяет вернуться к предыдущей базе. Проверка health подтверждает только запуск CouchDB и доступность базы, но не полноту нужных заметок.

После переключения проверьте статус сервиса:

```sh
docker compose ps
docker compose logs --tail=100 couchdb
```

Не используйте `docker compose down -v` для обычной остановки: команда удалит volume.
